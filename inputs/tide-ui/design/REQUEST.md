# 任务：UI 技术实现路线（《潮汐记事》· Godot 4.7.2）

## 背景

游戏已经能完整玩通（岸上 + 海上），但界面全部是在 `shore.gd` / `main.gd` 里用代码硬拼的：没有 Theme 资源，
没有控件封装，一个按钮都没有，交互靠一行字提示按哪个键。

设计侧已经定稿，放在本目录：

- `UI-SPEC.md` —— 逐元素规格（坐标、四边描边、圆角、字号、颜色、动效、验收清单）
- `tokens.json` —— 同一套数字的机器可读版
- `prototype.html` —— 单文件可点原型（岸上/海上 × 晨午昏夜 + 六个覆盖层）
- `preview-*.png` —— 五张实况渲染图

现有代码在 `../code/ui-shore.gd`、`../code/ui-sea.gd`（从工程里摘出来的 UI 段落）。

## 要你产出

一份**技术实现路线**，落在本目录 `IMPLEMENTATION-PLAN.md`（走 PR 也行），必须覆盖下面七件事：

1. **现状核对**：逐条对照 `tokens.json` 与 `ui-shore.gd` / `ui-sea.gd`，列出每个现有元素（顶栏、状态行、提示行、
   对话面板、信纸、瞬时消息）现在的坐标/字号/颜色，和规范要求的差多少，缺什么。
2. **Theme 资源设计**：用几个 `.tres`、怎么分；`StyleBoxFlat` 要定义哪几个（分别绑给谁）；字体与字号怎么映射到
   Theme（规范里的 12/14/16/18/22/26/34 对应 Theme 的哪几个默认字号）；颜色常量放 Theme 的 color 槽还是脚本常量，
   给出理由。
3. **控件封装**：键帽（KeyCap）用什么做（Button + StyleBox 还是 `_draw` 自绘），操作条/状态行/提示行三行的容器结构，
   对话面板与信纸（RichTextLabel + 分页）怎么实现，代码放哪个文件。
4. **三个新界面**（结算卡、暂停设置、鱼篓）的节点树草案 + 交互状态机（键位、焦点、esc 返回、暂停时输入怎么吞）。
5. **层级与状态**：常驻/瞬时/叙事/覆盖四层在 Godot 里用什么承载（CanvasLayer 层号、`process_mode`、`mouse_filter`），
   覆盖层打开时底下那层要不要暂停、怎么暂停。
6. **迁移顺序**：分几步做，每步改哪个文件、怎么验证（能跑 + 截图对比 `preview-*.png`）、风险在哪、回滚点在哪。
7. **不做的事**：不改美术资源，不改玩法逻辑，不引入第三方 UI 插件。

## 硬约束

- Godot 4.7.2，1280×720，`stretch/mode = canvas_items`
- 所有配色、字号、间距、圆角、动效时长以 `design/tokens.json` 为准，**不得自创**
- 规范里三条硬规则（铜边左 2 上右下 1 / 一屏只用深墨系或纸米系 / 字号只许七个值）是验收项
- 文档用中文，给到文件级、函数级的改动点，不要写"建议统一风格"这类空话

## 交付

`IMPLEMENTATION-PLAN.md` + 一次 PR。路线里如果发现规范本身有矛盾（比如某个元素在 1280×720 里摆不下），
把矛盾单独列一节，不要自己改规范。
